Thirteen families, from a 5×5 grid to dm_control's dog. Everything except the
Gymnasium wrappers is Mojo: the tabular grids, the classic-control dynamics, the
2D and 3D physics, the robot and LIBERO scenes, the arcade engines and the Atari
2600 emulator. That is what lets an environment step inside the same GPU
pipeline that trains on its output.

:::note[Humanoid is 45-dimensional, not 376]
Gymnasium's `Humanoid-v5` observation includes contact forces and inertia terms,
which push it to 348–376 dimensions. noeira's Humanoid observes
`(NQ − 2) + NV = 22 + 23 = 45` — position and velocity only. Older copies of the
project README and slide deck quote 376; the source is authoritative and the GPU
example reads `HumanoidModel.OBS_DIM  # 45`.
:::

### Arcade — native GPU engines

Two observation modes each: a compact game-state vector (`OBS_MODE=0`) or a
4×84×84 grayscale frame stack (`OBS_MODE=1`).

| Environment | Clean obs | Actions |
|---|---|---|
| Pong | 6 | 3 |
| Breakout | 7 | 4 |
| Space Invaders | 8 | 4 |

## Where the dimensions live

A recurring source of confusion, so worth stating plainly: for the physics3d
environments the dimensions are on the **model**, not the config.

```mojo
comptime OBS_DIM = HumanoidModel.OBS_DIM      # 45
comptime ACT_DIM = HumanoidModel.ACTION_DIM   # 17
```

HalfCheetah and Ant additionally expose them on their config
(`HalfCheetahConfig.OBS_DIM`), which is what the older examples use. Both resolve
to the same compile-time constant. If one does not exist, try the other.

## Choosing one

**Learning the framework** — GridWorld or CartPole. No GPU, seconds to run,
obvious correct behaviour.

**Testing a continuous-control algorithm** — Pendulum first (3 dimensions,
fast), then HalfCheetah (no early termination, so returns are smooth and easy to
compare).

**Testing exploration** — MountainCar or FrozenLake. Both have sparse or
deceptive reward that punishes greedy agents.

**Stressing the physics engine** — Humanoid. 45 observations, 17 actuators, and
contact-rich dynamics that expose solver problems immediately.

**Comparing against published continuous-control numbers** — the
[DeepMind Control](/environments/dm-control/) ports, whose returns are bounded
by 1000 and comparable across tasks. They are parity-gated against MuJoCo but
none has a training result documented yet.

**A robot you can own** — [SO-ARM101](/environments/robots/), which has a
[real-hardware path](/robots/).

**Pixel-based agents** — the arcade engines in `OBS_MODE=1`. Native and
GPU-batched, so they are far faster than the Atari emulator for training; the
emulator exists to validate them.
