Combinators are modules that take modules. Because composition happens in the
type system, a network is built by nesting types rather than by appending to a
list at runtime.

```mojo
from mojo_rl.nn.combinators.sequential import Sequential
from mojo_rl.nn.combinators.residual import Residual
from mojo_rl.nn.combinators.repeat import Repeat
from mojo_rl.nn.combinators.parallel import Parallel
```

## The core four

**`Sequential[A, B, C, …]`** — chain modules. Output dimensions must match the
next input, checked at compile time.

```mojo
comptime Net = Sequential[
    LinearReLU[784, 256],
    LinearReLU[256, 128],
    Linear[128, 10],
]
```

**`Residual[M]`** — add the input to the output. Requires `IN_DIM == OUT_DIM`.

```mojo
comptime Block = Residual[Sequential[Linear[D, D], ReLU[D], Linear[D, D]]]
```

**`Repeat[M, N]`** — `N` independent copies in sequence. Each gets its own
parameters; the count is compile-time, so there is no runtime loop.

```mojo
comptime Trunk = Repeat[Block, 6]      # six residual blocks
```

**`Parallel[A, B, …]`** — run several modules on the same input and combine.
This is where `ARITY` earns its place: the combinator handles children with
different input counts uniformly.

## The rest

| Combinator | Purpose |
|---|---|
| `BranchConcat` | branch, then concatenate outputs |
| `SkipConcat` | concatenate a skip connection — U-net style |
| `ProjectedResidual` | residual with a projection when dimensions differ |
| `RepeatConditional` | conditioned stack — Dreamer 4's transformer |
| `Tokenwise` | apply a module per token |
| `InitWith` | override the initializer for a subtree |
| `StopGradParams` | freeze a subtree's parameters |

:::caution[`Tokenwise` and eval-mode state]
Setting an attribute through `Tokenwise` did not propagate to the wrapped
module for a while, which meant BatchNorm stayed in **training mode during
planning**. If you wrap a module carrying eval-mode state, verify the mode
actually reaches it.
:::

## ComputeGraph

`Sequential` covers chains. When a loss has a genuine DAG shape — several
inputs, shared subgraphs, multiple outputs — use the named-node builder in
`combinators/compute_graph.mojo`.

```mojo
from mojo_rl.nn.combinators.compute_graph import ComputeGraph
```

Nodes are declared with names and wired by reference, and the graph resolves the
backward order itself. This is what the world-model losses use, where a single
update touches an encoder, a dynamics net, several prediction heads and a KL
term that has to flow to two places.

For a plain feed-forward network, `Sequential` is simpler and generates better
code — reach for `ComputeGraph` when the topology actually needs it.

## Compile-time cost

Deep parameterization is not free, and this is where it bites first.

:::caution[Instantiation depth can explode compile times]
Two known failure modes, both hit in this repository:

- **A long chain of calls in one function** (~80+) can trigger an inliner
  explosion. Extract helpers.
- **A deep `comptime` loop building nested modules** can hang the compiler
  outright. The LeWM depth-loop and eval-block cases both needed the body pulled
  into a separate function.

If a build stops making progress rather than failing, suspect instantiation
depth before suspecting your code.
:::

A related practical note: probe compilation with `mojo build --emit=llvm` rather
than a full link. macOS `ld` rejects the very long generic symbol names this
design produces, so a link failure can be a false negative that has nothing to
do with your code.
