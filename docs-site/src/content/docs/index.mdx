## Today's RL stacks are stitched together

A typical reinforcement-learning project runs on NumPy for arrays, PyTorch for
networks, MuJoCo for physics and Gymnasium for environments — four libraries in
two or three languages, held together by Python glue.

That glue costs you three things. Every language and library boundary adds
overhead and data copies. Versions drift, and the CPU↔GPU round-trips across
those boundaries are hard to optimise. And you cannot fuse physics, networks and
environment stepping into a single GPU pipeline, because no one owns all three.

## One language. One GPU pipeline. No glue.

mojo-rl rebuilds the whole stack — physics, neural networks, algorithms,
rendering — in Mojo, so the entire loop compiles together and the data never
leaves the device.

## Why Mojo

Mojo gives Python's ergonomics with the performance of C and first-class GPU
programming, so the whole RL loop can live in a single optimizable codebase.
Custom kernels target both CUDA and Metal from the same source.

The pieces that make this concrete — compile-time network composition, the trait
hierarchy, and how a batched environment stays resident on the device — are
covered in [Concepts](/concepts/architecture/).
