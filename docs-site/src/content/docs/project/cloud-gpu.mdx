A laptop proves correctness; NVIDIA timings, CUDA-graph capture and the
large training runs happen on a rented GPU. The repository ships a `Dockerfile`
for that box.

## The image

The `Dockerfile` at the repository root builds on
`runpod/base:1.0.3-cuda1300-ubuntu2404` — Ubuntu 24.04 with CUDA 13 and SSH
already configured — and adds:

- `git`, `vim`, `htop`, `rsync` and `curl`;
- pixi, installed under `/opt/pixi` and put on `PATH`, also for interactive SSH
  sessions;
- a **pre-warmed package cache**: the build copies `pixi.toml` and `pixi.lock`,
  runs `pixi install -e nvidia`, then deletes the unpacked environment. The
  downloaded packages stay in the image, so on the box `pixi install -e nvidia`
  only unpacks and links them — about a minute instead of about ten;
- `MODULAR_NVPTX_COMPILER_PATH=/usr/local/cuda/bin/ptxas`, the same
  [ptxas redirection](/project/toolchain/#nvidia-the-ptxas-redirection) the
  `nvidia` environment sets.

Build it for `linux/amd64` (from an Apple Silicon Mac, through `buildx`) and
push it to your registry:

```bash
docker buildx build --platform linux/amd64 -t <dockerhub-user>/noeira-runpod:latest --push .
```

The cache is keyed on the lock file the image was built from. After a toolchain
upgrade, rebuild the image, or the first `pixi install` downloads again.

## Using it

**RunPod** — create a template with:

| Setting | Value |
|---|---|
| Container image | `<dockerhub-user>/noeira-runpod:latest` |
| Container disk | 20 GB |
| Volume disk | 50 GB, mounted at `/workspace` |
| Exposed TCP ports | 22 |
| Start command | empty — the base image handles it |

**Vast.ai** — use the image directly as a custom template; no start command is
needed.

## CUDA 13, sm_120 and older cards

Because the build uses the system `ptxas`, what the box can compile for is
decided by the container's CUDA:

| Container | `ptxas` | Covers |
|---|---|---|
| CUDA 13 (this image) | 13.x | `sm_120` — RTX 50xx, e.g. the RTX 5090 |
| CUDA 12.8 | 12.x | `sm_89` — RTX 40xx |

Either works on a driver of 570 or later. Check what you were given with:

```bash
pixi run -e nvidia gpu-info
```

which prints the GPU's name, compute capability, memory and driver version.

:::caution[Numbers from a Mac do not transfer]
Metal and CUDA differ in JIT, floating-point corners and which paths run at
all — CUDA-graph capture is a no-op off NVIDIA. Re-run a gate that passed on
Metal on the box before trusting it, and benchmark only on the hardware you
report. See [Testing](/project/testing/).
:::

## Setting up the box

```bash
cd /workspace
git clone https://github.com/noeira/noeira.git
cd noeira
pixi install -e nvidia
```

Then:

1. **Credentials.** Create a `.env` in the project root. The training drivers,
   the dataset and project commands and the asset resolver read it directly — nothing
   needs to export it to the shell:

   ```bash
   NOEIRA_CLOUD_URL=https://cloud.noeira.ai
   NOEIRA_CLOUD_API_KEY=...
   HF_TOKEN=...          # only to push datasets to the Hugging Face Hub
   ```

   See [noeira cloud](/tooling/monitor/). `.env` is gitignored.

2. **The cache.** Asset packs and downloaded datasets go to `~/.cache/noeira`
   unless `NOEIRA_CACHE` is set. On a pod whose home directory is on the
   container disk, point it at the volume so the cache survives a restart:

   ```bash
   export NOEIRA_CACHE=/workspace/.cache/noeira
   ```

3. **The shims.** The C shims are built per platform and are not in git, so a
   fresh box has none of them. Build the ones your run needs — at least
   `build-http` for anything that talks to noeira cloud or downloads data, and
   `build-qhull` for mesh models:

   ```bash
   pixi run -e nvidia build-http
   pixi run -e nvidia build-qhull
   ```

   The CUDA intercept library is built by the `nvidia` environment's
   activation on first use. See the
   [shims table](/project/toolchain/#native-shims).

4. **Assets.** Fetch the packs a run needs before starting it, so a long
   training run does not stall on a download:

   ```bash
   pixi run -e nvidia assets-status
   pixi run -e nvidia assets-pull libero
   ```

:::tip[Compile time is the cost of a rented box]
A large driver can take minutes to build on the box before it runs. For
iterating on one driver, the [precompiled package](/project/toolchain/#the-precompiled-package)
(`build-pkg`, then `run-pkg`) takes most of that out of each rebuild.
:::
