**Deep Deterministic Policy Gradient** is the ancestor of the off-policy
continuous-control family. A deterministic actor, a single critic, and Gaussian
noise for exploration.

```mojo

```

## The idea

For discrete actions, [DQN](/algorithms/dqn/) picks the best action by taking a
`max` over the network's outputs. With continuous actions that maximisation is
itself an optimization problem — you cannot enumerate the options.

DDPG's answer: train a network to *output* the maximising action. The actor is
updated by pushing its actions toward higher critic values, backpropagating
through the critic into the policy.

```
actor loss  = −Q(s, π(s))          # maximise the critic's estimate
critic loss = (Q(s,a) − y)²        # y = r + γ·Q′(s′, π′(s′))
```

That trick — differentiate through the critic to improve the actor — is what
every algorithm in this family inherits.

Exploration is external: Gaussian noise added to the actor's output, since a
deterministic policy explores nothing on its own.

## Building it

```mojo
from mojo_rl.deep_agents.ddpg import DDPGAgent
from mojo_rl.deep_agents.training.blocks import UniformSampleGpuStep

var agent = DDPGAgent[
    "gpu",
    UniformSampleGpuStep[OBS_DIM, ACT_DIM, BATCH, REPLAY_CAPACITY],
    ActorNet,
    CriticNet,
](ctx=ctx, actor_lr=1e-4, critic_lr=1e-3, gamma=0.99, tau=0.005)
```

The actor is a deterministic network ending in `Tanh` scaled to the action
range — not a [`StochasticActor`](/algorithms/sac/), which is what SAC uses.

```bash
pixi run mojo run -I . examples/pendulum_ddpg.mojo
pixi run mojo run -I . examples/half_cheetah/ddpg_half_cheetah_training.mojo
```

## The problem

DDPG is brittle, and understanding why explains the two algorithms that follow.

The critic is trained on targets built from its own estimates at the actor's
chosen action. Wherever the critic happens to overestimate, the actor moves
*toward* that region — because that is where the critic says the value is high.
The next target is then computed there, reinforcing the error.

This is not noise that averages out. The `max`-like structure of the update
**selects** for optimistic error. A run can look healthy for a long time and
then collapse.

[TD3](/algorithms/td3/) fixes this with three targeted changes;
[SAC](/algorithms/sac/) fixes it differently, with a stochastic policy and an
entropy term.

## When to use it

Honestly: to understand the family. TD3 is DDPG with the known fixes applied and
is strictly better; SAC is better again on most tasks.

DDPG remains useful as a **baseline** — if a new environment trains under TD3 but
not DDPG, that is informative about how much the stabilisation matters there.
